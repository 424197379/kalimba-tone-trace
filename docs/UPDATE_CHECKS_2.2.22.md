# 2.2.22 主动更新验证

练习页与曲库版本号旁的刷新按钮，以及原“立即更新”提示，统一使用 `src/app-update.js`。主动操作先读取在线版本，再检查当前更新注册、等待下载和启用，最后刷新当前地址并核对实际运行版本。错误或超时恢复按钮，允许重试；不清空本地存储、不注销离线应用。

已在隔离的 Chromium 测试浏览器与本地可切换版本服务器中复现旧问题并验证修复。测试中模拟的2.2.23仅用于验证升级，不是本次发布版本。

| 场景 | 操作与结果 |
| --- | --- |
| 旧版失败证据 | 两张2.2.21页面均显示更新提示；A页更新到模拟2.2.22后，在B页点击旧提示。B页仍显示2.2.21，按钮持续禁用。 |
| 相同场景复测 | 两张新版页面同时收到模拟下一版本；A页更新后，B页点击旧提示也更新成功，显示实际版本。 |
| 从旧缓存进入新入口 | 先安装2.2.21缓存，再加载2.2.22 HTML并点击新刷新按钮；成功升级，保留青花瓷选择和地址参数。更新模块单独由HTML加载，避免依赖旧缓存中的练习脚本提供入口。 |
| 下载失败与重试 | 模拟新版曲库资源返回503，页面显示下载失败，仍可使用旧版，刷新按钮恢复可用；恢复资源后重试成功。 |
| 本地曲谱保留 | 通过真实导入界面添加测试曲目；下载失败和后续成功更新后，本地曲谱内容逐字一致，仍能搜索。 |
| 离线与恢复联网 | 离线点击刷新显示离线提示并恢复按钮；联网后重试，显示真实的最新版状态。 |
| 当前已是最新版 | 点击或使用键盘Enter触发，不循环刷新，显示“已是最新版本”。 |
| 页面显示 | 390×844手机曲库与1280×800练习页显示34像素圆形刷新按钮；原有横屏精简练习布局仍隐藏版本栏，可从换曲进入曲库更新。21键及练习布局保留。 |

新版离线壳资源安装使用 `cache: reload`，在线版本查询不从离线缓存取值；其余运行时缓存策略及音频架构保持原有行为。不能保证用户当时遇到的情况就是本次复现原因，但本次已经消除该可重复的失效更新路径。

发布前执行曲库校验、生成、14首曲谱回归、适配检查及全部运行脚本语法检查。曲谱数据无修改；全库仍为52版本、7045目标音、0错误及154条已有提示。真实iOS/PWA设备尚未现场测试。
