## Confirmed problem and minimal fix

In2.4.38, a stationary progress drag inside a final A/B phrase could run past
both B and the normal whole-song tail. Wrapping deliberately waits until the
drag finishes, but the ordinary song-completion branch did not. Demo stopped
while the A/B handles remained active; the next own-play action could start a
long countdown from the beginning of the entire song. Own-play could also
finish, and a subsequent restart cleared the selected loop.

This was reproduced in both the actual production-function runtime and the
own-cloud webpage with Birthday,104 BPM,1.40x,A=22/B=25. A three-second pointer
hold near the end of the progress track visibly ended demo with A/B still on
and Pause disabled. It was not inferred from a static code pattern.

The fix adds `!practiceLoopRange` to the two ordinary song-completion guards.
A selected loop retains ownership of its ending while a progress drag defers
wrapping. Release returns to the existing A preparation without finishing the
session. No timing, pointer, preparation, audio or stall thresholds change;
ordinary sessions without a loop still reach their normal song ending.

All57 source-song JSON files,12 internal archives, generated songs, sample
bytes, library code and compiler skill are byte-identical to38. Song-store
changes only its version constant: actual import prompt, parser and source
rules are unchanged. No new source, listening or physical approval is implied.
