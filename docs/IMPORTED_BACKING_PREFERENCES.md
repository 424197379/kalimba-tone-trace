# Imported backing: explicit identity and remembered choice

Local preview2.4.25. Supported external `autoAccompaniment` already played via
the legacy accompaniment button in2.4.24. This change provides a consistent
selector and per-song preference, rather than repairing a nonexistent route.

## Product contract

Newly imported songs start at 无伴奏 even when their source says enabled by
default. Eligible external support is labeled 导入伴奏 in the selector and song
library; the app does not silently thin its attacks, soften its supplied gain,
or approve its harmony. Physical targets remain the canonical single melody.
The app plays the chosen support in own mode and melody plus support in demo.

A manual choice is remembered for that canonical song. Off remains off.
Switching songs or reloading can restore on only for the same selected support
identity. Melody, BPM, extent, provider, support notes/onsets/durations/roles,
velocity or configuration volume changes invalidate that remembered on choice.
The content signature does not certify source accuracy, sample timbre, effects,
user playback speed or subjective sound quality.

## One provider selection

`getSongAccompanimentProvider` in song-store returns the chosen whole source,
configuration and kind. Practice support has priority. External auto fallback
requires both song and provider to be local, share the same base and have an
explicit compatible complete melody, BPM and extent. Prefer the current source,
then deterministic existing version-rank/id order. Do not combine layers.
The same selection drives practice controls/configuration, remembered identity,
metadata badges and initial-duration calculation.

Compatible existing built-in practice support keeps its light-v1 signature
exactly. A fixture generated by executing the frozen2.4.24 signature code locks
all five existing complete strings. Imported-auto has a separate identity and
preference choice; it cannot reinterpret an old light preference. Existing
built-in original-only accompaniment retains its session-only button behavior,
including prior mismatch isolation. No new source or backing is introduced.

## Storage and session behavior

Per-song schema1 records add imported-auto as a distinct allowed choice. Reads
fail closed for invalid, corrupted, future or mismatching records. Writes retain
unknown fields and check readback; damaged/future records are not overwritten.
Manual selection still works within the tab if storage is denied or fails.
The old global enable flag is not migrated. Another tab's choice does not hot
switch this tab's active session; re-entry/reload can read the updated preference.

User-set volume continues to override source defaults. Tempo, pause/continue,
A–B looping and existing long-frame admission remain shared with normal practice.
No new audio engine, scheduling timeline or OS-specific handling is added.

## Verification and source boundary

Actual parser → save → normalized library → production session tests check the
four-target/two-support fixture: own emits exactly two support notes, demo emits
six total notes, with gains intact. Tests also cover dense imported data without
reduction, provider priority, aliases, wrong roles/BPM/extent, mixed origins,
removed or changed source, invalid preferences, failed storage and cross-tab
behavior. The real copied AI prompt and compiler schema state that the imported
label is provenance only. Top-level practiceAccompaniment is still rejected on
new imports; this UX change does not relax that field-loss guard.

See VERIFY_2.4.25.md for full gate, real webpage actions and clean replay results.
Neither stored approval nor successful playback proves musical source fidelity.
