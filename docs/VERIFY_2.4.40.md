## Confirmed loss and fix

Repeated members in one JSON object previously kept only the last value during
native parsing, before the existing note validator could inspect earlier
content. The real import handler then saved the surviving melody/backing/batch,
reported success and cleared the original input. Preexisting songs were not
deleted. An independent raw-text audit confirmed16 loss cases among31 cases.

The new-input path still uses native JSON grammar validation, then scans the
original string with an explicit container stack and a per-object Map of decoded
keys. Every same-object duplicate is rejected before schema projection or
storage, including escape-equivalent spellings, equal values and metadata.
Different objects can reuse names; string contents, case and Unicode-normalized
variants are not conflated. No old stored-data reader or storage migration is
changed. Error messages provide bounded/escaped paths and exact first/repeated
source positions; the existing failure handler preserves the entire input,
previous library, selection and filters. See `IMPORT_DUPLICATE_FIELDS.md` for
precedence, deliberate compatibility narrowing and safe repair guidance.

The actual copied AI prompt, compiler skill and JSON reference are synchronized.
This protects against ambiguous content loss; it cannot establish which music
is correct or repair a source-transcription mistake.
