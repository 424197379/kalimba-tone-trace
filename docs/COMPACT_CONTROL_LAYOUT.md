# 窄练习视口的控制区（2.4.45）

## 修复的问题

旧版横向紧凑布局把曲名、暂停、换曲、听／弹、速度和伴奏强行放在一行。
首列可以收缩到零，但里面的暂停和换曲按钮仍有固定宽度，结果会盖到相邻按钮。
页面没有横向滚动条，也不能据此认定控件没有重叠。

实际云浏览器在普通150%缩放、410×352 CSS像素时，《生日快乐》的轻伴奏选择框
使换曲按钮中心落在“自己弹”上；175%、351×302时，暂停和换曲中心分别落在
“自己弹”和“听示范”上。这是浏览器缩放后的实际渲染与只读命中检查，
不是手机实机或触摸手感认证。

## 小范围适配

- 有效横向宽度不超过560 CSS像素的紧凑练习区分成两行：曲名、暂停、换曲在首行；
  听／弹、速度和当前可用伴奏控件在第二行。
- 速度滑块允许缩小，保留数值和原有键盘操作；无伴奏、轻伴奏、原版伴奏和导入伴奏
  使用同一排布规则，原来应隐藏的控件仍隐藏。
- 同时不超过320 CSS像素高时，缩减琴键区高度和进度周围留白，避免两行控制区
  把下落轨道挤没。21个琴键、音名、八度点、循环手柄和播放事件均不删除。
- 软件旋转分支使用互换后的有效宽高及对应视口单位。宽于560像素的现有紧凑单行
  布局与普通桌面布局不变。

仅修改样式；没有调整音符、速度语义、音频准备、暂停／继续、导入校验、AI提示或
编谱技能，也未改变Service Worker缓存策略。

## 长说明与很矮的视口

长谱面说明保持完整、可读，原本需要默认展开的说明仍默认展开，不自动折叠、缩字
或截掉后半段。在很矮的视口，展开说明会占用下落轨道，不能把“控件可点”当成
“适合完整演奏”的通过结论。请先阅读并主动收起说明，或减小浏览器缩放后练习。

307×264下，《诀别书》说明展开时仍没有有效下落空间，并有琴键底部裁切；
这是明确保留的极短视口限制。相同合成内容和完整生产警示的对照中，旧44样式的
键底位于297.84，新样式位于277.84，都超过264，故两者都不计为该状态通过。
正常候选页面收起说明后，键底回到250，全部21键与各操作可见，仍可重新展开全文。
351×302及410×352的说明展开状态也仅计为阅读／控制可达，不作为正常轨道验收。

## 验证边界

实际检查包括615×528宽布局、410×352窄布局，以及307×264压力场景；记录控件
矩形、中心命中、键区与轨道边界，而非只看文档宽度。正常版本更新后，36个内置
曲目与空导入稿保留；轻伴奏曲的示范、尾段结束、循环、暂停后变速及准备后继续，
以及合成导入伴奏的保存、练习、完整结束和按名称删除均通过实际页面操作。
合成曲清理后回到36个内置入口、零本地测试曲、空原稿。

在307×264，生日快乐和合成导入曲的下落区为50像素；收起说明的曲目为24像素。
这些是有限空间下的功能检查，不保证与大视口相同的可读性或实体跟弹舒适度。
本轮软件旋转分支做了静态对应检查，但没有完成真实竖屏渲染验收；不得将上述
横向浏览器结果扩大为所有手机、所有缩放和方向的保证。

最终离线检查、真实Node服务器和源码补丁复现另见本版验证记录。
