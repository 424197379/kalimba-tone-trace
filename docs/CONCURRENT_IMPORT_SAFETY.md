# 并页本地曲库写入保护

## 修复范围

v2.4.33 的实际复现：先打开两个曲库页，A 导入 id 为
`qa-same-source-id` 的「并页旧谱」（C4）；不刷新 B，再导入同 id 的
「并页另一版」（E4）。B 的启动时曲库快照仍为空，旧保存代码按同 id
移除原记录，结果只剩后一首。单页正常重复导入能生成 `_2`，并不能覆盖
这个旧页面写入问题。

本次只改本地曲库的导入／删除提交边界和曲库页刷新。没有修改乐谱数据、
音频调度、跟弹判定、练习页运行时、伴奏默认规则或 Service Worker 缓存策略。

## 提交约定

- 导入不再把曲库页的启动快照传给解析器。在获得写入锁后，读取当时曲库，
  校验整批输入，再保存。
- `saveCustomSongs` 在实际提交时重新严格读取原始存储数组；从不按新 id
  过滤旧记录。即使解析和保存之间出现新的同 id 记录，保存也会重新分配新 id。
- 保留原数组中每个既有记录的内容和次序，包括当前版本无法读取的未来版本、
  格式有问题的记录、未知字段、历史伴奏资料。保存会重新序列化数组，不承诺
  保留 JSON 空白字符或原始字节排版。
- 原始记录的字符串 `id` 与 `baseSongId` 都参与占位；没有显式 base 的旧
  `_chord`／`-chord` 记录还会占住其旋律组。旧读取逻辑会 trim／字符串化的 base 也参与占位；当前无法显示的记录也不能被覆盖。
- 新导入任一版本的 id 或 base 冲突时，整个新组一起换 base。新旋律和新编配
  保持同组；后续批次成员继续避开已分配的 id。旧旋律、旧编配、旧速度和旧
  伴奏选择仍归原 id，不会被接到新曲上。新曲没有旧曲的伴奏选择记录，沿用
  现有默认关闭逻辑。
- 整批校验失败、空批次、不完整保存成员或重复保存 id 都不能保存前半批。
  原存储不是合法数组（包括空字符串、坏 JSON、未来格式包装器）、读取失败
  或写入失败时，停止保存；不把原内容当空库清理。
- 删除从同一个严格原始快照选出当前可读的目标记录，再保留其余原始项。
  与可见曲目重用 id 的不可读／未来记录不是删除的附带目标。

## 跨页面同步与边界

曲库页导入和删除都使用同源 Web Locks 名称 `kalimba-custom-songs-write`，
以 `exclusive` 和 `ifAvailable: true` 请求。锁内只有同步的读取、校验、
重编号和一次存储写入；绘制等待、提示等待和刷新 UI 不在锁内。

- 两个参与此约定的页面依次成功写入时，后者看到前者的结果。
- 真正重叠的请求可能只有一个立即获得锁。未获锁的请求明确提示稍后重试，
  保留完整粘贴输入；重试成功后添加独立新曲。这里不承诺两次重叠点击都成功。
- 不排队等待锁，也不使用会留下后台延迟写入的 `Promise.race` 超时。失败后
  不会在用户不知情时晚到写入。
- Web Locks 缺失、请求被拒绝或取锁失败时，导入和删除都停止持久化写入。
  提示检查 HTTPS／localhost 环境与 Web Locks 支持，不承诺换浏览器一定解决。
  原有曲库读取、查看和练习不需要该写入锁。
- 同一页导入／删除忙碌期间，相关提交按钮禁用且处理器防重入；双击确认
  不会再次删除或用第二次失败覆盖第一次成功提示。完成或失败后恢复按钮。
- `saveCustomSongs`、`saveCustomSong` 和删除同步 helper 仍用于内部测试／恢复
  操作，本身不是跨页面事务。新的 UI 入口调用它们时必须持有同一个锁。
- `localStorage` 本身没有跨页面读改写事务。旧版已打开页面、不遵守锁约定的
  其他代码、开发者工具直接改存储或同步 helper 的直接调用不受此互斥保护。
  不能声称新旧混合页面或任意外部写入都绝对安全。使用修复版写入前，应先
  更新／重新打开其他曲库页。

## 被动刷新

曲库页在 `pageshow`、自定义曲库 `storage` 事件和清空存储事件时重新读取
曲库并刷新曲卡及本地管理列表。仍有效的当前页面选择保留，另一页导入时
写入的共享“当前歌曲”不会抢走本页已经显示的选择。显式链接按原有规则
解析，已不存在的选择走现有安全回退。

被动刷新严格读取存储；暂时读取失败会保留上次成功的列表／选择并提示，
不会把读取失败当作歌曲已删除。提示位于折叠导入面板之外，不覆盖导入结果；
恢复后只清除此刷新提示，原本明确选择的本地曲目仍可恢复。

这些刷新不清空未提交 JSON，不改搜索词／难度，不写入选择、速度、伴奏
偏好或练习记录，不重写 URL，也不会启动播放。练习历史／速度事件只执行
原有曲卡重绘；无关存储事件不重绘曲库。

`song-library.js` 入口，包括真实事件注册、导入／删除处理器、渲染和实际
`song-store.js` API；DOM、Web Locks 和计时 API 使用最小可控模拟。

覆盖：两个预先打开页面的旧快照复现；解析后再发生碰撞；旋律／编配整组
换 id；只碰撞编配 id；多个同源批次组；未来／异常原记录占位；旧伴奏和
偏好隔离；合法 V1、notation、V2 和 wrapper 批量导入；同时请求、失败保稿
和手动重试；没有锁、拒绝锁、锁忙、读取／配额失败及坏存储；整批失败；
存储事件和 bfcache 风格返回；导入与删除两种顺序；重复确认和同页互斥；
删除时保留不可读同 id 原记录。

这些是自动化模拟回归，不替代实际 Chromium 多页面、真实 Web Locks、PWA
