# 换曲时立即暂停

## 问题与修正

2.4.43及之前，“换曲”只设置新页面地址。旧练习通常会在浏览器发出
`pagehide` 后暂停，但加载曲库较慢、失败或被停止时，旧页面还可能停留。
期间正在播放的示范会继续走；尚未完成的声音准备也可能在离开意图之后启动。

2.4.44在设置曲库地址之前调用已有的 `pausePractice()`。不等待新页面响应，
立即停下当前练习、取消旧的播放请求和动画回调，并停止现有发声。
发声仍按原有的短渐隐停止，不声称零毫秒声学截断。
这不是播放架构、音符时序或离线缓存策略的改写。

## 如果仍停留在旧页面

- 保留当前暂停位置、播放模式、实际速度和A/B循环。
- 不自动恢复；需点击“继续”，按现有准备拍再接着弹。
- 原已暂停的会话不被重置，空闲状态也不会被变成自动播放。
- 已处于开头或A点准备拍时，继续位置仍按原有规则回到首个可弹音；不承诺保留
  一段已经进行到一半的倒数。
- 晚到的声音准备成功或失败不能重新启动旧请求或覆盖当前暂停状态。
- 浏览器已经收到的全屏请求本身未必可撤销；这里只取消它后续的旧播放准备，
  不声称能阻止全屏界面最终出现。

导航仍使用原有曲目id和地址；曲库筛选、导入草稿、速度记忆及歌曲内容不变。
没有新增恢复旧曲谱入口，也不产生新的实体和弦目标。

## 证据的分层

受控真实云浏览器复现使用完整应用代码和合成测试音序。未修复的 `src/app.js`
与冻结2.4.43逐字节相同；仅测试副本的请求层将曲库导航响应延迟20秒。
点“换曲”后，浏览器仍显示加载中，旧示范进度从0:19继续到0:29，音块继续移动。
这确认了实际页面上的活动播放问题，不是主观试听结论。

延迟的音频恢复、采样准备、继续倒数、全屏完成及失败分支使用生产函数提取的
隔离回归检查。它们验证请求作废、状态保留和晚到结果，不被冒称为全部都在真实
浏览器中逐一制造过的故障。旧版本相同测试的失败与修正后结果分别保留。

测试副本只含应用文件、合成歌曲及空的缓存归档占位。没有复制受保护的源图、
私有谱稿或用户本地数据，没有修改生产Service Worker的缓存策略或服务器访问
规则；临时副本不随发行包交付。修正后的实际网页及完整运行结果见本版验收记录。
