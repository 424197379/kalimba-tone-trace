# 2.4.49：测试站白屏恢复基线

本文件记录已冻结的 2.4.49，不代表后续夜间候选版已经验收。歌曲、音频与 2.4.48 相同。

## 事故、修复与真实恢复

2.4.48 在本地普通 200 页面通过后发布到测试站，但真实托管站把 `.html` 导航重定向到简洁地址。缓存的 HTML `Response.redirected` 为 true；直接将它用于浏览器手动重定向模式的导航会导致 `ERR_FAILED`。2.4.48 随后回退，不能把其本地通过记作线上升级通过。

2.4.49 仅对成功、同源、同一应用页面的 HTML 重定向响应重建不带重定向链的响应，保持正文、状态与响应头。未知目标、错误类型、失败及不完整响应不冒充页面。救援自动激活仅限 2.4.49 检测到 2.4.48 缓存，而且先完成整个新应用壳与样本安装；不清空本地曲谱或草稿。

2026-10-13 15:07 UTC，测试站发布 2.4.49。原来出现白屏的云浏览器资料中，普通重新访问后先显示回退的 2.4.47，再通过页内更新进入 TEST 2.4.49并显示实际更新结果。未清空浏览器存储。这是原受影响资料的真实恢复观察。

## 播放观察的更正与限制

恢复后的早期云浏览器检查出现起点处“播放卡顿，已暂停”。后续确认，工具操控的网页标签并非原生 Chromium 前景标签，旧本地预览仍在前景。因此该记录只能算后台／环境观察，不能作为用户所述普通前景卡住的复现。

独立体验者切到真实前景后，2.4.49 的《生日快乐》1.00x、无伴奏示范连续走完约 11 秒并正常结束；真实用户手势全屏也成功。该观察不证明所有歌曲、设备或长期播放均无问题，也不将后台条件解释为用户现场原因。

夜间候选版另行检查首个可见准备帧、冷音频图建立后的声音过期校验及其边界。这些受控时间不变量与原用户现场的因果归属分开记录。音乐听感、实体琴演奏、微信系统栏及操作系统来电行为均未在本轮作通过保证。
